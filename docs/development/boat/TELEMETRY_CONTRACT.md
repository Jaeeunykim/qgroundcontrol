# Boat 상태정보 계약 초안: 선박 → PX4/Pixhawk → QGC

- 작성일: 2026-11-17
- 상태: 합의용 초안. 실제 PX4/Pixhawk의 송신 규격·지원 여부가 확정된 문서가 아님.
- QGC 분석 기준: `v5.1.5` / `3a67d31f0c36bf3fe38ec52970d250a89d0aaf67`
- 관련 문서: [구현 계획](IMPLEMENTATION_PLAN.md), [저장소 README](../../../README.md)

## 1. 상태정보 정의가 필요한 이유

통신 경로가 `선박 장비 → Pixhawk/PX4 → MAVLink → QGC`여도 메시지 이름만으로 장비 값의 의미가 확정되지는 않는다.
PX4가 어떤 값을 어떤 메시지·단위·장치 인덱스로 발행하며, 원천 장비가 끊겼을 때 무엇을 보고하는지 합의해야 한다.
QGC가 정상적으로 패킷을 수신했다는 사실은 측정값이 유효하거나 최신이라는 보증이 아니다.

이 계약은 선박에서 PX4로 들어오는 상태정보와 PX4에서 QGC로 나가는 상태정보의 대응을 정의한다.
badaMux의 내부 버스·제어 방식이나 전용 메시지를 QGC 공식 Boat 지원의 필수 의존성으로 추가하는 문서가 아니다.
기존 MAVLink 메시지가 의미를 표현하면 우선 재사용하고, 부족한 항목만 별도로 조사·제안한다.

## 2. 책임과 계약의 상태

| 주체 | 책임 |
| --- | --- |
| 선박 장비/중계 장치 | 실제 측정·고장·장비 인스턴스·원천 갱신 여부를 PX4에 전달 |
| PX4 담당 | 입력 값의 의미·유효성 확인, 필요한 단위 변환, uORB/stream 구현, MAVLink 발행·단절 보고 |
| QGC 담당 | 기존 수신 경로·Fact 활용, 소스별 상태 관리, 화면 의미·미수신/무효/만료 표시, 기체/세션 격리 |
| 통합 담당 | 버전·필드·주기·만료·지원 기능 확정, 로그/실측 대조, 운항 인수 결과 기록 |

MAVLink에 정의가 존재하는 것, 대상 PX4에서 송신하는 것, QGC가 해석하는 것, 원하는 UI가 있는 것은 서로 다르다.
아래 표는 표준 메시지 후보와 v5.1.5에서 확인한 일부 수신 경로다. 실선 발행은 모두 확인이 필요하다.
기본 항해 필수 항목과 엔진·러더 등 선택 장비 항목의 완료 조건을 분리한다.

### 두 구간의 정의와 연결

| 구간 | 확정할 내용 | 구현 책임 |
| --- | --- | --- |
| A: 선박 장비/중계 장치 → PX4 | 입력 프로토콜·메시지·출처, 단위·장치/축, 유효성·원천 시각·고장·입력 만료 | 선박 장비와 PX4 담당 |
| B: PX4 → MAVLink → QGC | A의 어떤 값을 어떤 표준 메시지·인스턴스·주기로 발행하는지, 변환·무효 보고·QGC Fact 대응 | PX4와 QGC 담당 |

PX4가 단순히 원본 프레임을 라우팅하는지, 입력을 해석해 uORB 상태와 새로운 MAVLink 메시지로 발행하는지도 구분한다.
전자는 원본 메시지 규격·출처가 유지되고, 후자는 PX4가 변환·인스턴스·원천 갱신 의미를 책임져야 한다.
QGC의 연결 상대가 Pixhawk라는 사실만으로 수신 payload가 표준 메시지가 되지는 않는다.

아래 항목은 A 구간을 합의하기 위한 논리적 데이터 목록이다. 실제 wire 필드명이나 신규 메시지 ID 선언이 아니다.
장비에 없는 항목은 미지원으로 기록하며, 기본 Boat 항해를 위해 모든 장비 항목을 강제하지 않는다.

| 입력 ID | 선박에서 PX4로 전달할 상태 | A 구간에서 정의할 사항 | B 구간 연결 |
| --- | --- | --- | --- |
| IN-01 | 실제 엔진/추진기 RPM | 장치 ID, 실제/추정 여부, rpm 단위·방향 부호, 유효 범위·무효값 | 의미에 맞는 EFI/ESC 등의 표준 후보와 연결 |
| IN-02 | 엔진 온도 | 측정 위치: 냉각수/헤드/배기가스, 단위·scale·유효성·센서 오류 | 같은 물리량을 표현하는 필드만 사용. 맞는 필드가 없으면 미확정 |
| IN-03 | 실제 러더 각도 | 단일/다축 ID, 센서 실측/엔코더 환산 여부, 중심·부호·deg·보정 기준 | 출력 채널 값과 분리. 적합한 표준 표현은 조사 필요 |
| IN-04 | 추진·조향·기어 상태 | 요청/실제 상태, 활성/비활성/전후진·중립 지원 여부, 인터록 | 단순 armed/운항 모드로 대체하지 않고 표현 가능 범위 확인 |
| IN-05 | 장비 고장·경고 | 코드/비트 의미, 심각도, 동시 오류·알 수 없는 비트·복구/해제 조건 | 이벤트/기계 판독 가능한 상태 및 표시 정책으로 대응 |
| IN-06 | 장비 연결·데이터 품질 | 원천 갱신 시각, sequence/boot 식별 가능 여부, 필드별 valid, 입력 단절/만료 | PX4가 마지막 값을 반복 송신해도 원천 단절을 감추지 않도록 계약 |

IN-01~06 각각에 실제 입력 메시지·필드·버전, PX4 수신 모듈/uORB topic, 출력 메시지·필드, 시험 로그를 연결한다.
선박 측 정의가 이미 있다면 이를 받아 대조하며, QGC 쪽에서 장비 내부 프로토콜을 새로 정하지 않는다.

## 3. 기본 항해 상태정보 매핑

| 항목 | 메시지·필드 후보 | wire 단위/의미 → 표시 | QGC 경로·합의 사항 |
| --- | --- | --- | --- |
| Boat 식별·armed·모드 | `HEARTBEAT.type`, `autopilot`, `base_mode`, `custom_mode`, `system_status` | Boat=`MAV_TYPE_SURFACE_BOAT(11)`, PX4 펌웨어 식별. armed·운항 모드·실제 이동을 분리 | Vehicle/FirmwarePlugin. 타입을 숨기거나 임의로 Boat로 치환하지 않음. Rover 타입을 보고한다면 펌웨어/호환 방침부터 결정 |
| 펌웨어·지원 기능 | `AUTOPILOT_VERSION`, 지원되는 모드/기능 보고 | 버전·커밋·capabilities → 지원 여부 | HEARTBEAT만으로 Go To/위치 유지/역추진/접안 지원을 판단하지 않음 |
| 위치 | `GLOBAL_POSITION_INT.lat/lon`, `GPS_RAW_INT.fix_type` 등 | 위경도 degE7 → deg. 위치 추정·GNSS 품질을 구분 | Vehicle/GPS Fact. 위치 `(0,0)` 자체를 무효로 판단하지 않음. 실제 소스·유효성 조건 확정 |
| 대지속도 SOG | `VFR_HUD.groundspeed` 또는 `GLOBAL_POSITION_INT.vx/vy` | m/s, 또는 cm/s → 수평 속력 m/s. 사용자 단위로 표시 | 현재 groundSpeed Fact의 VFR_HUD 경로 활용 검토. 속도 소스 우선순위·전환 규칙 합의. STW로 표기하지 않음 |
| 선수방위 Heading | `ATTITUDE.yaw`/quaternion 또는 `GLOBAL_POSITION_INT.hdg` | rad 또는 cdeg → 북 기준 deg | 현재 heading Fact는 자세 yaw 경로 사용. 북 기준·센서/추정 출처·fallback·무효값 합의 |
| 이동방향 COG | `GPS_RAW_INT.cog`, 필요 시 수평 속도에서 계산 | cdeg → deg. `UINT16_MAX`는 미확인 | GPS `courseOverGround` Fact 경로 존재. Heading과 별도 표시. 저속 시 품질/표시 기준은 미확정 |
| 미션 진행 | `MISSION_CURRENT`, `MISSION_ITEM_REACHED` 등 | 항목 순번·도달/진행 상태 | MissionManager. 계획 항목 순번과 wire 순번 대응, 완료와 물리적 정지 구분 |
| Home·다음 WP 거리/ETA | `HOME_POSITION`, 계획·현재 위치·속도 등 | 좌표·m·s. 계산값과 수신값 구분 | 기존 MissionController/Vehicle 계산 우선 검토. 미유효 위치·저속에서 ETA를 확정값으로 보이지 않음 |
| 전원·센서 상태 | `BATTERY_STATUS`, `SYS_STATUS` | 메시지별 단위·sentinel → 기존 Fact | 배터리/센서 상태가 선박 전체 또는 추진계 정상의 보증은 아님. 장비별 인덱스 확인 |
| 경고·오류 | 지원되는 `EVENT`, `STATUSTEXT`, 기계 판독 가능한 상태 플래그 | 심각도·오류 코드·활성/복구 상태 | 기존 알림·이벤트 활용. 자유 형식 문구만 파싱해 제어 가능 여부를 결정하지 않음 |
| 명령 결과 | `COMMAND_ACK`와 모드/미션 상태 보고 | IN_PROGRESS·수락·거부·시간 초과·결과 미확인 | 기존 요청 처리 활용. ACK 수락은 실제 이동·목표 도달·물리 정지 증거가 아님 |

기존 QGC 모델은 [VehicleFactGroup](../../../src/Vehicle/FactGroups/VehicleFactGroup.cc),
[VehicleGPSFactGroup](../../../src/Vehicle/FactGroups/VehicleGPSFactGroup.cc),
[Vehicle](../../../src/Vehicle/Vehicle.cc), [MissionManager](../../../src/MissionManager/MissionManager.cc)를 확인한다.
표의 대체 소스를 모두 새로 구현하겠다는 뜻은 아니다. 실제 PX4 stream과 기존 Fact의 소스 정책을 대조해 최소 변경을 선택한다.

## 4. 선택 장비 상태: 기존 표준 활용과 표현 공백

| 항목 | 후보 | 정의해야 할 의미·제한 |
| --- | --- | --- |
| 내연기관 RPM | `EFI_STATUS.rpm` | 어떤 ECU/엔진의 실제 RPM인지 정의. 기존 EFI Fact 경로가 있으나 대상 PX4 stream 발행은 별도 확인 |
| 전동 추진기 RPM | `ESC_STATUS.rpm` 등 | 모터 인덱스·회전 방향·측정 출처 정의. 엔진 ECU와 ESC 상태를 혼용하지 않음 |
| 엔진 온도 | `EFI_STATUS`의 특정 온도 필드 | 냉각수·실린더 헤드·배기가스 온도는 서로 다름. 예를 들어 냉각수 온도를 실린더 헤드 필드에 대입하지 않음 |
| 추진 출력·스로틀 | `VFR_HUD.throttle`, 적합한 `EFI_STATUS` 필드 등 | 요청값/제어기 출력/스로틀 실측/추력을 구분. %만 같아도 같은 물리량이 아님. 역추진 부호·기어는 별도 확인 |
| 서보/액추에이터 출력 | `SERVO_OUTPUT_RAW`, `ACTUATOR_OUTPUT_STATUS` | 출력 채널 값이며 실제 러더 각도가 아님. 출력 단위·채널 매핑을 확인하고 각도 실측처럼 표시하지 않음 |
| 실제 러더 각도 | 적합한 표준 메시지 조사 필요: 미확정 | 센서 실측/엔코더 환산/추정 여부, 축, 좌현/우현 부호, deg, 원천 유효성·시각 정의. 이 문서에서 신규 ID를 만들지 않음 |
| 실제 제어 주체·추진/조향 고장 | 기존 모드/이벤트로 표현 가능한 범위 조사 | 모드나 GCS heartbeat만으로 독점 제어권 보유를 확정하지 않음. 필요한 별도 필드/표준화 여부는 후속 결정 |

QGC에는 [VehicleEFIFactGroup](../../../src/Vehicle/FactGroups/VehicleEFIFactGroup.cc) 등 기존 Fact가 있다.
값의 의미가 맞는 경로를 먼저 재사용한다. 선택 장비 값이 없더라도 기본 Boat 항해 기능은 사용할 수 있어야 한다.
새로운 범용 메시지가 필요하면 MAVLink/PX4/QGC에 각각 필요한 변경과 검토를 분리한다.
프로젝트 전용 `BADA_*`/`BADAMUX_*` 데이터를 공식 QGC가 자동 지원한다고 가정하지 않는다.

## 5. 항목별 계약에 반드시 기록할 내용

| 분류 | 필수 기록 |
| --- | --- |
| 식별 | 요구사항 ID, 필수/선택, 선박 system ID, 허용 component, 엔진/배터리/축 인덱스 |
| 원천 | 실제 센서/장비, PX4 수신 지점·uORB topic·MAVLink stream, 변환인지 원본 전달인지 |
| wire 규격 | dialect/XML 커밋, 메시지·필드·타입·단위·scale·부호·좌표 기준·유효 범위 |
| 유효성 | 미지원·미수신·미확인·무효의 표현, sentinel/NaN/valid 비트, v2 확장 필드 생략의 의미 |
| 시간 | 측정 시각·발행 시각·QGC 수신 시각, 시계 기준·재부팅·wrap 처리, 원천 갱신 시각 확인 가능 여부 |
| 주기 | 기대/최소 수신 주기, 링크 대역폭, 요청 가능 여부·거부/미지원·실측 주기, 만료 임계값 |
| 표시 | QGC Fact·QML 표시명·사용자 단위·정상/만료 UI, 복수 소스 우선순위 |
| 제어 연계 | 어떤 조작에 필수인지, 무효/만료 시 표시만 바꿀지 조작도 제한할지, 복구 조건 |
| 검증 | 패킷/로그·실측 비교·원천 단절 시험·버전·담당자·합의일·판정 |

주기 행의 기대/최소 수신 주기와 실제 수신 주기는 구분한다. 아래 결정표의 수치는 합의 전까지 미확정이다.

### 상태 모델과 만료

아래는 내부 표시 의미 제안이며 신규 MAVLink enum 선언이 아니다.

| 상태 | 판단과 화면 |
| --- | --- |
| 지원 안 됨 | 해당 센서/기능이 없음이 확인됨. 기본 Boat 사용을 불필요하게 막지 않음 |
| 미수신 | 현재 세션에서 유효 데이터가 아직 없음. `—` 또는 상태 문구, 임의 0 사용 안 함 |
| 유효 | 허용된 출처·인스턴스, 값/valid 조건과 합의한 시간 조건 충족 |
| 무효 | 메시지는 도착했지만 sentinel·범위·센서 품질 등의 조건 미충족 |
| 만료 | 합의한 갱신 제한 초과. 마지막 값 표시 시 오래된 값임을 함께 표시 |

- 원천 센서가 끊긴 뒤 PX4가 마지막 값을 새 패킷으로 반복 송신하면 QGC 수신 시각만으로 원천 만료를 판단할 수 없다.
  PX4가 무효 상태를 보고하거나 원천 갱신 시각/valid 정보를 제공할 수 있는지 확인한다.
- `EFI_STATUS`처럼 원천 timestamp/valid가 충분하지 않은 경우 보장 가능한 범위를 명시한다.
  모든 필드를 무조건 NaN으로 보내는 방식도 표준 계약 확인 없이 확정하지 않는다.
- 유효한 0, `UINT16_MAX` 등 필드별 sentinel, 미수신을 구분한다. 다른 필드의 무효 규칙을 복사하지 않는다.
- 서로 다른 장치의 boot time을 직접 빼지 않는다. 수신 만료는 로컬 단조 시계, 원천 age는 합의된 기준으로 계산한다.
- 기체 변경·단절·재연결·재부팅 후 이전 세션 상태와 명령 결과가 재사용되지 않게 한다.
- PX4/GCS 연결 정상과 원천 엔진·러더 통신 정상을 별도로 다룬다.

2026-11-24 구현 보완: Boat 기본 계기 값은 기존 QGC의 전체 통신 단절 판정에서 NaN으로 전환하며,
재연결 후 각 stream의 새 수신으로 복구한다. 마지막 지도 좌표는 보존하지만 새 위치 수신 전 Home 거리 계산에는
사용하지 않는다. 이는 D04의 개별 stream 만료 시간 또는 D05의 원천 센서 생존성을 확정한 것이 아니다.
상세 범위는 [P4 테스트 기록](P4_TESTING.md)의 연결 복구 절에 기록한다.

## 6. PX4와 먼저 결정할 항목

각 행은 PX4 담당·QGC 담당·통합 담당이 확인할 합의 항목이다. 이름/수치를 임의 기본값으로 확정하지 않는다.

| ID | 결정 | 현재 상태 |
| --- | --- | --- |
| D01 | 보드, PX4 버전·커스텀 커밋, XML/dialect 커밋, 실제 `HEARTBEAT.type`·autopilot | PX4/Pixhawk 구성만 확인. 나머지 미확정 |
| D02 | 시작·중단·재개·Go To·RTL의 지원 명령/모드, 도착 후 동작, 위치 유지·역추진 지원 | 미확정. ArduPilot Hold/Loiter 의미를 사용하지 않음 |
| D03 | A 구간 입력 메시지와 B 구간 표준 메시지/필드 대응, component·인스턴스, 소스 우선순위·단위 | 표준 후보와 입력 목록만 정리. 실제 캡처·합의 필요 |
| D04 | 항목별 수신 주기·최소 가용 주기·만료 시간·복구 조건·요청 정책 | 미확정. 모든 값을 10Hz 또는 공통 시간 초과로 고정하지 않음 |
| D05 | 원천 장비 단절·무효/오래된 데이터의 PX4 발행 방식과 QGC 표시 | 미확정. 단순 중계 heartbeat로 원천 정상 판단 불가 |
| D06 | wire 좌표 프레임·고도 필드·속도·Home·미션 항목 요구사항 | 미확정. UI 고도 숨김과 wire 값을 별도로 정의 |
| D07 | 선택 장비의 RPM/온도/타각·실제 제어 주체·고장 상태, 표준 표현 공백 | 미확정. 기본 항해 완료와 선택 장비 완료 분리 |
| D08 | QGC Fact/QML 경로, 현재 공통 모델의 유효성 보완 범위, 회귀/영속 설정 호환 | 구현 단계에서 구체화 |
| D09 | 시험 장비·담당자·허용 오차/지연·실선 인수 절차·증거 위치 | 미확정 |

`MAV_CMD_SET_MESSAGE_INTERVAL`로 원하는 stream을 요청할 수 있어도 PX4의 구현·수락·실제 수신을 확인해야 한다.
QGC의 UI 갱신 주기, PX4 상태 발행 주기, 조종 명령 주기는 서로 다른 설정이다.

## 7. 계약 완료와 검증

- [ ] 기본 항해 필수 필드에 D01~D06·D09의 담당·버전·값·판정 기준 연결.
- [ ] 사용하는 선택 장비의 IN-01~06에 A 구간 입력→PX4 변환→B 구간 출력의 추적표와 시험 증거 연결.
- [ ] 정상/유효한 0/sentinel/NaN/누락 필드/범위 밖 입력의 표시 확인.
- [ ] Heading과 COG가 다른 상황, 저속·위치 무효·복수 소스의 우선순위 확인.
- [ ] 원천 센서 단절과 PX4-GCS 단절을 따로 재현하고 최신/만료 판정 확인.
- [ ] 다른 선박·component·장치 인덱스, 늦은 응답, 재부팅·재연결에서 격리 확인.
- [ ] 지원하지 않는 메시지·주기 요청 거부·저대역폭을 실제 수신 결과와 대조.
- [ ] 요청·ACK·상태 변화·물리 동작을 별도로 기록. 선택 장비의 출력값을 실측값으로 오인하지 않음.
- [ ] PX4/QGC/XML 커밋과 샘플 로그·패킷·측정 비교·미실행 제한을 인수 기록에 연결.

기존 BadaNavi 연동 기록은 선박 측 요구사항을 찾는 참고 자료다. 그 구현·시험 결과를 QGC나 최신 PX4의 검증 결과로 이전하지 않는다.
