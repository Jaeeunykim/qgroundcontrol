- 문서 버전: `0.1.0-draft`
- 작성일: 2026-11-17
- 목적: 기본 장비 연결부터 수동 조종·항로 자동운항·선택적 고급 자율운항까지 제품 인터페이스 정의
- 상태: 설계·합의용 초안. 제품 펌웨어 구현·상호운용·실선 시험 완료를 뜻하지 않는다.

여기서 제안하는 장비 제어·제어권·제품 전용 메시지가 공식 QGC에 포함된다고 가정하지 않는다.

## 기본 구조

```text
GCS(QGC/BadaNavi/제품 앱)
          ↕ MAVLink: 운항 의도·계획·상태
      Pixhawk / PX4 ← 선택적 선내 자율운항 컴퓨터
          ↕ MAVLink: 장비 명령·실제 상태
        badaMux
          ↕ CAN / EtherCAT / GPIO / 선박 센서
    엔진·추진기·기어·러더·부가 장비
```

기본 책임은 PX4의 항법·항로 추종과 badaMux의 장비 구동·로컬 보호다.
자율운항 컴퓨터는 선택 사항이며, badaMux 자체가 경로계획기나 충돌회피기라는 가정을 두지 않는다.

## 구현 단계

| 단계 | 제품 기능 | 선행 조건 |
| --- | --- | --- |
| M0 | 장치 식별·버전·상태·진단·읽기 전용 연결 | 공통 XML/주소·센서 의미·유효성 합의 |
| M1 | 제어권·수동 조종·출항 점검·추진/조향·정지·통신 만료 | M0 + 장비 한계·정지/기어/재시도 규칙 |
| M2 | WP 항로·속도·중단/재개·복귀·운항구역·장애 복구 | M1 + 실제 PX4 무인선 지원·항법 품질·현장 인수 |
| M3 | 선내 경로계획·장애물/AIS·작업/측량·선택적 접안 | M2 + 기능별 센서·계획기·검증 환경 |

M3 기능을 광고하거나 사용할 수 있으려면 해당 capability와 기능별 인수 결과가 있어야 한다.
모든 선박에 내연기관·클러치·다축 러더·후진 기능이 있다고 가정하지 않는다.

## 근거 스냅샷과 해석

- 기존 `bada.xml`: BadaNavi의 MAVLink 저장소 커밋
  [`f16192a8737e30f994e80b23d71ed1e33e2e47d7`](https://github.com/BadaProject/mavlink/blob/f16192a8737e30f994e80b23d71ed1e33e2e47d7/message_definitions/v1.0/bada.xml).
  선언을 확인한 것이며 현재 장비의 실행 지원을 증명하지 않는다.
- 로컬 BadaMux 분석: 커밋 `319fadf700e24c37feb13ae6e402b15a8ee79946`.
  MAVLink handler에 TODO가 있고 watchdog의 스레드 생존 감시도 TODO다.
  이 오래된 로컬 스냅샷을 최신 제품 펌웨어로 간주하지 않는다.
- 이전 BadaNavi 연동 기록에는 더 나중의 규약·앱 구현이 있다.
  다른 시점의 펌웨어·XML·앱 지원을 합쳐 하나의 검증된 시스템으로 표기하지 않는다.
- `P_*`는 신규 논리 메시지 제안명이다. 실제 wire 메시지·숫자 ID·enum 값·CRC를 아직 할당하지 않는다.
- `SHALL`은 이 초안을 채택할 때 충족해야 할 제품 요구사항, `SHOULD`는 권장사항이다.
  기존 펌웨어가 이미 충족한다는 의미가 아니다.

먼저 인수 계획의 결정표 D01~D18을 합의하고, 실제 사용할 기능의 메시지·장비·시험 결과를 고정한다.
